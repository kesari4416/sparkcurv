# SparkCurv repo — audit and fix summary

**Date:** 2026-10-17
**Repo state:** `4348bea` plus uncommitted changes. Nothing has been committed or pushed.
**Full details:** `AUDIT.md`, the line-by-line findings plus the Emergent inventory.
**How to run it:** `README.md`

> This file describes security weaknesses. Don't commit it to a public repository.
> No secret values appear in it.

---

## 1. What was found

The repo is a React (CRA + craco) marketing site with a blog admin panel, plus a FastAPI + MySQL
backend. It was generated by the Emergent AI builder. The audit covered every tracked file and the
git history. The original state:

- The **backend could not start**: `JWT_SECRET` was required but missing from `.env`.
- The **frontend built**, but it would fail a CI build with warnings treated as errors.

### Critical
| Issue | Why it mattered |
|---|---|
| Live secrets committed to git | The MySQL password and Gmail app password were in `spark-backend/.env`. The production admin email and password were in plaintext in `memory/`, `PRD.md` and `test_reports/`. **The MySQL password and the admin password are the same string.** |
| Built-in backdoor admin | `admin@sparkcurv.com` / `SparkAdmin@2024` was the fallback in `server.py`, and that password is published in 4 test files. Emergent's own test report shows the account still worked. |
| Admin password reset on every restart | `seed_admin()` overwrote the admin password from env (or the default) at every boot. |
| Stored XSS that leads to admin takeover | Blog HTML was saved and rendered without cleaning. The editor accepted `javascript:` links, and the login token sat in `localStorage`, where injected script could read it. |
| Blog page showed no posts | The cards stayed at `opacity: 0`, because the scroll-reveal observer ran before the posts loaded. |

### High
- **Logout didn't end the session.** The cookie deletion was missing `Secure`, so browsers ignored it.
- **CORS ignored `CORS_ORIGINS`.** `localhost:3000` was always allowed, and the production origin was not.
- **The backend started "healthy" with no database.** Every route then returned 500, and `/api/health` returned 200 while leaking the internal error.
- **Contact form:**
  - no rate limit or spam protection;
  - no field-length limits;
  - visitor input went unescaped into the notification email;
  - sending the email blocked the server.
- **Uploads:**
  - the whole file was read before the size check;
  - the file type was taken from the client instead of the file's bytes;
  - nginx capped uploads at 1 MB while the app allowed 5 MB.
- **Frontend `.env` pointed at `http://localhost:8000`.** The backend runs on 8001, and uploaded image URLs were saved with that host baked in.
- **Crashes to a blank white page:**
  - any unknown `/application-development/...` URL;
  - any validation error in the admin panel.
- **Broken admin Media tab.** Clicking an image threw an error.
- **SEO canonical links pointed at routes that don't exist.** Two tool logos also 404 on Linux, because of filename case.
- **The home page downloaded about 21 MB:** a 2.1 MB logo shown on every page, 5600 px photos, and 4 autoplay videos.
- **Emergent dependency downloaded from Emergent's CDN.** If that URL disappears, `yarn install` fails.

### Medium and low (grouped)
- **Auth:**
  - no handling of expired sessions;
  - a global axios interceptor attached the token to every request;
  - no login rate limit.
- **Splash screen:** it delayed every page load, deep links included, by 2.5 s.
- **FAQ structured data:** it was re-injected about 45 times a second on the home page.
- **Blog post page:** the post body was unstyled, because the typography plugin was missing.
- **WhatsApp button:** it was hidden, yet the FAQ told users to click it. Its number also differed from the site phone.
- **Contact form:**
  - required fields had no asterisk;
  - the phone pattern was invalid in current browsers;
  - long text was silently rejected;
  - the service list had a typo, "Digital Grouth".
- **Missing basics:**
  - no 404 page;
  - no error boundary;
  - pages missing SEO;
  - page titles with a doubled suffix;
  - no social-share (`og:`) tags.
- **Accessibility:** menus without `aria-expanded`, a heading read out letter by letter, and keyboard-unreachable tag links.
- **nginx:**
  - no security headers;
  - images cached as "immutable" for 30 days.
- **Dead weight:**
  - 45 unused shadcn UI components and about 35 unused npm packages;
  - a chatbot that calls API routes that don't exist;
  - RAG/Redis backend scripts that aren't wired to anything;
  - 131 pinned Python packages where the server needs 13;
  - about 36 MB of unused images and videos.
- **Repo structure:**
  - broken `/app/...` symlinks;
  - a submodule with no `.gitmodules`;
  - a committed `.gitconfig` with the Emergent bot's identity;
  - two lockfiles;
  - `.gitignore` entries that matched nothing, which is how `.env` got committed.

### Found while fixing
- **Stale database reads.** The connection pool used `autocommit=False` and never committed its reads. Pooled connections kept serving old snapshots: an old password kept working after a change, and new posts could stay invisible.
- **`emergentintegrations` isn't on public PyPI.** `pip install -r requirements.txt` and the Docker build already failed on any machine outside Emergent.

## 2. What was done

### Secrets and repository
- **Stopped tracking secret files** (`git rm --cached`; the files stay on disk): both `.env` files, `memory/test_credentials.md` and a committed `.pyc`.
- **Redacted the passwords** in `memory/PRD.md` and `test_reports/*.json`.
- **Fixed both `.gitignore` files**, and added `.env.example` for the backend and the frontend.

### Backend (`spark-backend/server.py`)
- **Startup and admin accounts:**
  - It fails fast with a clear message if `JWT_SECRET` is missing, and exits if the database is unreachable at startup.
  - The admin seed runs only when no usable admin exists, and never overwrites a password.
  - Any account still using the leaked default password is locked at startup.
- **Login and sessions:**
  - Auth is cookie-only: httpOnly, `SameSite=Strict`, `Secure`. The token is no longer returned in the response body.
  - Logout clears the cookie properly.
  - Sessions are tied to the password hash, so changing a password signs out every session.
  - New `POST /api/auth/change-password` endpoint. Minimum password length is now 10.
- **Rate limits:**
  - Stored in MySQL, so they hold across all workers.
  - They cover login, contact and password change.
  - For login and password change, only failed attempts count.
- **Blog posts:**
  - HTML is cleaned with `nh3` when saved *and* when read, so old posts are cleaned too.
  - Image URLs must be uploads or http(s), and absolute `.../api/images/N` URLs are served as relative paths.
  - A duplicate slug returns 409, an empty slug 400, and a missing post a real 404.
- **Uploads:**
  - The read is bounded to the 5 MB limit.
  - The file type comes from the file's own bytes.
  - Images are served with long-term cache headers and `nosniff`.
- **Contact form:**
  - Field length limits.
  - A spam-trap field (`company_website`).
  - The notification email is HTML-escaped, with header-safe subject lines, and sent in the background.
- **Other:**
  - `/api/health` returns 503 when the database is down, without leaking details.
  - CORS reads `CORS_ORIGINS` and no longer always allows `localhost:3000`.
  - Database autocommit is fixed.
  - The deprecated startup hooks were replaced with a lifespan handler.
- **Removed:** the unwired `rag.py`, `ingest*.py`, `crawler.py` and `redis_memory.py`.
- **Requirements:**
  - `requirements-app.txt` holds the 13 real dependencies.
  - `requirements.txt` includes it plus the two Emergent lines, kept as requested.
  - `requirements-dev.txt` holds the test tools.
- **Dockerfile:**
  - no unneeded compilers;
  - runs as a non-root user;
  - a `.dockerignore`, so `.env` and caches stay out of the image;
  - the worker count is configurable.
- **Tests:**
  - New `tests/test_security.py`, with 18 regression tests.
  - Emergent's tests now read credentials from env, and three outdated assertions were updated.

### Frontend (`spark-frontend/`)
- **New shared helpers:**
  - `src/lib/api.js`: same-origin `/api`, cookie auth, and an error helper that always returns a string.
  - `src/lib/sanitize.js`: HTML cleaning with DOMPurify.
- **Admin:**
  - No token in `localStorage`.
  - An expired session sends you back to the login page.
  - Every error message is safe to render.
  - The Media tab works.
  - Uploads are validated, and image URLs are stored relative.
  - Unsaved changes ask before being discarded.
  - The editor blocks unsafe links, inserts images safely and cleans pasted content.
  - New change-password form in the Team tab.
  - The admin panel is code-split and loaded only on `/admin`.
- **Public site:**
  - The blog grid is visible.
  - Error boundary and 404 page.
  - Unknown subpages redirect to their parent page.
  - The canonical and SEO fixes listed in section 1, plus `og:` and Twitter tags.
  - The splash shows once per session, on the home page only, and doesn't block content.
  - The FAQ structured data is stable.
  - Blog post styling, a `?tag=` filter in the URL, and an error state with a retry button.
  - The contact form fixes listed in section 1.
  - Accessibility fixes.
- **Media:**
  - Large images were converted to WebP at display size; for example the logo went from 2.1 MB to 12 KB and a hero photo from 2.6 MB to 40 KB.
  - Three videos were re-encoded smaller, and every video has a poster.
  - The home videos play only while on screen.
  - 70+ unused or duplicate files were deleted.
- **Removed:**
  - `ChatBot`, `WhatsAppButton`, `Team.js` and `useScrollAnimation`;
  - all 45 `components/ui` files;
  - about 35 npm packages;
  - `package-lock.json` (the project uses yarn);
  - `components.json`.
- **`nginx.conf`:**
  - Upload limit raised to 6 MB.
  - Security headers on every route, plus a report-only CSP.
  - Correct caching: `index.html` is always revalidated, hashed files are cached long-term, images for 7 days.
- **New root `README.md`:** a step-by-step guide to running the project, written for beginners.

### Verification
| Check | Result |
|---|---|
| Backend test suite (59 tests) against real MariaDB 10.11 | **Pass**, 3 runs in a row |
| Upgrade from a database seeded by the *old* server | Backdoor account locked, legacy XSS post served clean, old image URLs made relative |
| `CI=true` production build | **Pass**, 0 warnings |
| Real `nginx.conf` (nginx 1.26) serving the build + API proxy | Headers, caching, SPA routing and a 3 MB upload all correct |
| Headless Microsoft Edge, 15 user-facing checks | **15/15 pass** (login, cookie flags, error display, Media tab, blog grid, XSS blocked, 404s, logout, no page errors) |

## 3. What is left

### Only you can do these
1. **Change the passwords:**
   - the MySQL password, which is the same string as the admin password;
   - the Gmail app password;
   - the admin password, via Team tab → Change Password.
2. **Add `JWT_SECRET` to the production `.env`.** The backend won't start without it.
3. **Delete the locked `admin@sparkcurv.com` account** in the Team tab after deploying.
4. **Docker:** run with `--env-file .env`. The `.env` file is no longer copied into the image.

### Decisions waiting on you
- **Git history:** the secrets are still in old commits. Removing them means a history rewrite and a force-push.
- ~~**Emergent removal**~~: **done** (see `AUDIT.md` section 4). `pip install` and the Docker build now work outside Emergent.
- **Content Security Policy:** it's report-only. Enforce it after checking the browser console with GA4 and Tawk.to running.
- **Cookie consent:** GA4 and Tawk.to load without a consent banner. That's a legal and business decision.
- **Website copy:**
  - "30+" vs "27+" projects, and "2+" vs "5+" years. Left unchanged.
  - The WhatsApp button was removed and one FAQ sentence reworded. Restore it if you want it back, with the correct number.
- **Lockout trade-off:** 10 failed logins in 15 minutes locks that admin email for 15 minutes. Someone who knows the email can trigger it.

### Not fixed or not tested
- **Two videos are still large:** `aiml3.mp4` (3.7 MB, 58 s) and `application2.mp4`. Re-encoding made them bigger, so they now load only on scroll; trimming them would need a content decision.
- **Partner logos 2 and 3** are SVGs wrapping large bitmaps.
- **Not tested:**
  - real email sending through SMTP;
  - Safari and iOS;
  - the production server itself.
- **Images inside blog content** use relative `/api/images/...` paths. They break if the API is ever moved to a different host than the website.
- **Toolchain:** Create React App 5 is deprecated. It works, but a move to Vite or Next.js fits naturally with the planned redesign.
- **Windows dev only:** running uvicorn with 2 or more workers occasionally hangs requests (reproduced, then isolated to multi-worker mode). Use one worker locally; production runs Linux.
